# cad-agent-ts

TypeScript agent server using next-ws WebSocket with multi-provider AI support and proactive inspection-based CAD correction loop.

## Requirements

### WebSocket transport

The agent MUST accept WebSocket connections at a configurable route via next-ws and SHALL maintain session history per connection with TTL cleanup.

#### Scenario: WebSocket connection established

- GIVEN the Next.js server is running
- WHEN a client connects to the configured WS route
- THEN a session SHALL be created with unique sessionId
- AND session history SHALL be initialized empty

#### Scenario: Session TTL cleanup

- GIVEN a session has been idle for the configured TTL period
- WHEN the cleanup timer fires
- THEN the session history and cached resources SHALL be released

### Multi-provider dispatch

The agent MUST support providers: chat tier (minimax, glm, kimi, deepseek, free models), messages tier (sonnet, opus, qwen, minimax-m3), and gemini (gemini-pro). Go tier models SHALL use ZEN_GO_BASE.

#### Scenario: Provider routing for chat tier

- GIVEN provider=glm is selected
- WHEN the agent dispatches a user message
- THEN the request SHALL be routed to the chat-compatible endpoint

#### Scenario: Provider routing for Go tier

- GIVEN provider=deepseek-v4-pro is selected
- WHEN the agent dispatches a message
- THEN the request SHALL be routed via ZEN_GO_BASE

#### Scenario: Invalid provider rejected

- GIVEN a provider name not in the registry
- WHEN the agent initializes
- THEN an error SHALL list valid providers

### CAD tools

The agent MUST provide tools: runCadCode, inspectCadModel, listOutputs, readReference. Tool results SHALL be in streaming format compatible with the frontend.

#### Scenario: runCadCode generates model

- GIVEN user message "generá un cubo de 50mm" with provider=glm
- WHEN the agent calls runCadCode
- THEN box(50, 50, 50) code SHALL be generated and executed
- AND a GLB model SHALL be returned to the frontend

#### Scenario: inspectCadModel returns geometry facts

- GIVEN a model was generated by runCadCode
- WHEN inspectCadModel is called
- THEN bounding box, volume, collision count, and snapshot SHALL be returned

### Proactive inspection loop

The agent MUST run inspectCadModel automatically after every runCadCode call. The agent SHALL NOT use the reactive error-classify-retry pattern.

#### Scenario: Inspection after code generation

- GIVEN runCadCode completes successfully
- WHEN the tool result is processed
- THEN inspectCadModel SHALL be called automatically
- AND inspection results SHALL be fed back to the agent

#### Scenario: Collision detected triggers correction

- GIVEN runCadCode returns a model with collisionCount > 0
- WHEN inspectCadModel detects the collision
- THEN the agent SHALL receive the collision data
- AND the agent SHALL correct the code in the next iteration

#### Scenario: Maximum correction iterations enforced

- GIVEN a user request requires geometric correction
- WHEN 10 correction iterations are exhausted
- THEN the agent SHALL stop and report the last result

### Image analysis pipeline

The agent MUST support image input (data URLs) and SHALL run dual analysis via Kimi GO + MiniMax M3 GO for providers without native vision.

#### Scenario: Image with non-vision provider

- GIVEN user sends an image with provider=deepseek (no native vision)
- WHEN the agent processes the request
- THEN the image SHALL be analyzed by Kimi + MiniMax before CAD generation
- AND the text description SHALL be passed to the CAD agent

#### Scenario: Image with vision-capable provider

- GIVEN user sends an image with provider=gemini (has native vision)
- WHEN the agent processes the request
- THEN the image SHALL be passed directly to the provider with no dual-analysis pipeline

### Parametric model editing

The agent MUST extract Param definitions from generated code and expose them for frontend property panel tweaking.

#### Scenario: Params extracted from generated code

- GIVEN the agent generates code with Param.number('width', 50)
- WHEN the code is parsed after generation
- THEN width SHALL appear as a tunable parameter in the frontend

### Tier classification

The agent MUST classify requests as SIMPLE, MODERATE, or COMPLEX from keywords in the user prompt and SHALL include tier-specific directives in the agent prompt.

#### Scenario: SIMPLE tier classification

- GIVEN user message contains "box" or "cylinder" with a single feature
- WHEN the agent classifies the request
- THEN tier SHALL be SIMPLE
- AND coarse inspection settings SHALL be used

#### Scenario: COMPLEX tier classification

- GIVEN user message contains "gear", "assembly", or exceeds 60 lines estimated code
- WHEN the agent classifies the request
- THEN tier SHALL be COMPLEX
- AND fine inspection and snapshot SHALL be mandatory
